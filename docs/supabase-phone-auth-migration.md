# Supabase Phone Auth Migration Guide

## Part 1 Status: ✅ COMPLETED

The Send SMS Hook adapter has been implemented. This document guides you through completing the migration.

## Architecture Overview

**Before (Old System):**
```
User → Frontend → /api/otp/send → whatsapp_otps table → Engagelab
                                  ↓
                            reserve_login_otp RPC
                            complete_login_otp RPC
                            verify_login_otp RPC
```

**After (New System):**
```
User → Frontend → Supabase Phone Auth → /api/auth/hooks/send-sms → Engagelab
                                      ↓
                              auth.users table
                              (built-in OTP management)
```

## Part 3: Backfill Existing Users ⚠️ CRITICAL

**Why this is needed:**
- `auth.users.phone` has a UNIQUE constraint
- Current users: their verified phones are in `public.users.phone`, but `auth.users.phone` is NULL
- Without backfill: existing users logging in with phone will create NEW accounts (data loss!)

### Pre-flight Checks

Run these queries in Supabase SQL Editor to verify data integrity:

```sql
-- Check 1: How many users have verified phones in public.users?
SELECT COUNT(*) 
FROM public.users 
WHERE phone IS NOT NULL AND phone != '';

-- Check 2: How many users have phones in auth.users?
SELECT COUNT(*) 
FROM auth.users 
WHERE phone IS NOT NULL;

-- Check 3: Find potential conflicts (same phone, different users)
SELECT 
  p.phone,
  COUNT(DISTINCT p.id) as user_count
FROM public.users p
WHERE p.phone IS NOT NULL AND p.phone != ''
GROUP BY p.phone
HAVING COUNT(DISTINCT p.id) > 1;
-- Expected: 0 rows (no conflicts)

-- Check 4: Preview the backfill (what will be updated)
SELECT 
  u.id,
  u.email,
  p.phone,
  u.phone as current_auth_phone
FROM auth.users u
INNER JOIN public.users p ON u.id = p.id
WHERE p.phone IS NOT NULL 
  AND p.phone != ''
  AND u.phone IS NULL;
```

### Backfill Script

**⚠️ STOP and report to Luca if Check 3 returns any rows (phone conflicts)**

If all checks pass, create and run this script:

```typescript
// scripts/backfill-auth-phones.ts
import { getServiceSupabase } from '@/lib/supabase/service'

async function backfillAuthPhones() {
  const supabase = getServiceSupabase()

  // Get all users with verified phones in public.users but NULL in auth.users
  const { data: users, error: queryError } = await supabase
    .from('users')
    .select('id, phone')
    .not('phone', 'is', null)
    .neq('phone', '')

  if (queryError) {
    console.error('Failed to query users:', queryError)
    process.exit(1)
  }

  console.log(`Found ${users.length} users with phones to backfill`)

  let successCount = 0
  let errorCount = 0

  for (const user of users) {
    try {
      // Use Supabase Admin API to update auth.users.phone
      // This also sets phone_confirmed_at = now()
      const { error: updateError } = await supabase.auth.admin.updateUserById(
        user.id,
        {
          phone: user.phone,
          phone_confirm: true, // Mark as verified
        }
      )

      if (updateError) {
        console.error(`Failed to update user ${user.id}:`, updateError.message)
        errorCount++
      } else {
        console.log(`✅ Updated user ${user.id} with phone ${user.phone}`)
        successCount++
      }
    } catch (error) {
      console.error(`Exception updating user ${user.id}:`, error)
      errorCount++
    }
  }

  console.log('\n=== Backfill Summary ===')
  console.log(`Total: ${users.length}`)
  console.log(`Success: ${successCount}`)
  console.log(`Errors: ${errorCount}`)

  if (errorCount > 0) {
    process.exit(1)
  }
}

backfillAuthPhones()
```

Run it:
```bash
npx tsx scripts/backfill-auth-phones.ts
```

   let recaptchaToken: string | undefined
   try {
     recaptchaToken = await getRecaptchaToken("send_otp")
   } catch (error) {
     console.warn("reCAPTCHA failed, proceeding without token")
     // Continue without captcha - Supabase has its own rate limiting
   }
   
   const { error } = await supabase.auth.signInWithOtp({
     phone: normalized,
     options: {
       captchaToken: recaptchaToken, // Supabase validates this
     },
   })
   
   if (error) {
     if (error.status === 429) {
       setError(t("err_rate_limited"))
     } else {
       setError(t("err_send"))
     }
     setBusy(false)
     return
   }
   
   // Success - proceed to OTP entry
   setOtp(Array.from({ length: OTP_LENGTH }, () => ""))
   setOtpStatus("input")
   setOtpChannel("sms")
   setAttemptsLeft(MAX_OTP_ATTEMPTS)
   setCooldown(RESEND_COOLDOWN)
   setBusy(false)
   setPhase("otp")

   if (otpChannel === "email") {

       email: email.trim(),
       token: code,
       type: "email",

       setOtpStatus("failure")
       setBusy(false)

       setBusy(false)

## Key Differences: Old vs New

| Aspect | Old System | New System |
|--------|-----------|------------|
| OTP Generation | Custom (6 digits) | Supabase (6 digits) |
| OTP Storage | `whatsapp_otps` table | Internal (auth.sessions) |
| OTP Verification | Custom RPC + Engagelab | Supabase verifyOtp() |
| Phone Storage | `public.users.phone` | `auth.users.phone` (authoritative) |
| Rate Limiting | Custom Redis counters | Supabase built-in |
| reCAPTCHA | Manual verify + score check | Passed to Supabase (delegated) |
| SMS Delivery | Engagelab direct | Engagelab via hook |
| Expiry | 5 min (custom) | 60 min (Supabase default) |
| Cooldown | 60s (custom) | ~60s (Supabase built-in) |

## Troubleshooting

### "Invalid signature" errors in production

**Cause:** `SUPABASE_AUTH_HOOK_SECRET` mismatch

**Fix:**
1. Check Vercel env var: `vercel env pull .env.production`
2. Compare with Supabase Dashboard hook secret
3. Update Vercel: `vercel env add SUPABASE_AUTH_HOOK_SECRET production`
4. Redeploy

### SMS not received after migration

**Cause:** Engagelab template not configured correctly

**Fix:**
1. Check `ENGAGELAB_SUPABASE_TEMPLATE_ID` is set
2. Verify template has `{{code}}` variable
3. Check Engagelab Dashboard logs for failed sends
4. Test with [test-send-sms-hook.ts](../scripts/test-send-sms-hook.ts)

### Existing users create duplicate accounts

**Cause:** Part 3 (backfill) was skipped or failed

**Fix:**
1. Run backfill script immediately
2. Manually merge duplicate accounts if any were created:
   ```sql
   -- Find duplicates
   SELECT phone, COUNT(*) 
   FROM auth.users 
   GROUP BY phone 
   HAVING COUNT(*) > 1;
   ```
3. Merge data from new account into old account
4. Delete new account

### Rate limit errors more aggressive than before

**Cause:** Supabase's built-in rate limiting is stricter

**Solution:** This is by design. If too restrictive:
1. Check Supabase Dashboard → Authentication → Rate Limits
2. Adjust phone OTP rate limit (default: 3/hour per phone)
3. Consider adding custom rate limiting in the hook if needed
